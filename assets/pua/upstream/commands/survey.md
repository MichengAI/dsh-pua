If the argument is `quick`, ask only once about how this run went (very useful / so-so / no feeling / skip this time), and say up front that the rating is recorded locally only and never uploaded. If the user skips or does not answer, write no rating file at all; if the user explicitly chooses to record it, append one valid JSON line to `~/.pua/feedback.jsonl` using a write tool the host allows, containing a UTC timestamp, the real rating, the flavor actually used in this task, and an optional short summary — never the full chat log. Use JSON serialization instead of concatenating shell strings; if there is no write capability, only echo it in the current conversation and state that it was not persisted. With no AskUserQuestion (user-question tool), just ask one short question, and do not block the original task that already completed. After quick mode ends, do not enter the full survey.

Otherwise read the survey file `skills/pua/references/survey.md` under this run's actual plugin root; the root comes from the host's `CLAUDE_PLUGIN_ROOT` (plugin root directory) or the real install location of this command — do not guess a path relative to the business working directory. Use AskUserQuestion to guide the user part by part. Group 2-4 questions per part; move to the next part after the user answers. When done, if the host allows local recording, summarize into JSON and write to `~/.pua/survey-response.json`; with no question or file tools, complete it in the current conversation and do not pretend it was persisted.

**Local writes only, no upload.** Survey results stay on the user's own machine; PUA Skill has no network reporting capability at all. Do not try to POST it to any address.
