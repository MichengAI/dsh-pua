# 插件架构

更新时间：2026-09-12 23:43（Asia/Shanghai）

## 原文与接口

基线 PUA 3.5.1 / e6e6cd237ad17750d179674bff52f8184abea8fd；开发宿主 DSH 0.1.5-rc.2，兼容 0.1.2-rc.1、0.1.5-rc.1。SourceCatalog 先校验字节指纹再加载白名单，不执行原版脚本。核心、展示协议、路由完整进入 systemPrompt，模式追加原文及关联协议。`{{` 字面转义避免宿主插值，其余正文不改写。

V2 宿主将组装提示交给 `request.system`，V3 放入 `request.messages` 的 system 消息。产品仍使用 systemPrompt 服务；请求断言按实际宿主位置读取，不将字段变化误判为注入失败。

组合上限 192 KiB，超限失败不截断。15 风味 × 11 模式及 auto 均校验，当前约 52–101 KiB。pua_reference 仅允许清单内 Markdown，全量返回。

必需 commands、systemPrompt。可选 tools 注册资料和结果观察，settings 注册 michengai-pua，subprocess 提供 Git/Oracle。明确任务 followup，纠偏 steer，非任务控制不唤醒。

## Web 配置与会话覆盖

共享 Configuration/Zod 契约定义 12 个参数。全局字段 `enabled` 映射既有 settings 的 `alwaysOn`，保留 profile 已有值。仅插件设置页调用全局写入；命令不再调用 settings.update。会话配置使用 `command/run` + `command/done`，不新增 user/message 或模型可见 JSON，不会打断工具结果组。

配置按字段继承；null 表示删除覆盖，同值显式选择仍保留覆盖。settings 变化导致基线重新折叠，下一模型步骤读取最新结果。新命令成功前缀为 `PUA · 会话 · `，旧前缀仍按旧版激活/关闭重置普通角色的语义恢复。会话覆盖随日志持久化，不随浏览器刷新丢失；持久写盘仍由宿主负责。

`remote.ts` 经已鉴权的原生 Typert Gateway 暴露 getGlobal/setGlobal、getSession/setSession、startLoop/cancelLoop。全局保存使用 settings revision 乐观锁，会话保存检查配置版本；未知会话、非法字段和过期版本返回错误。配置仅针对已经加载的 Agent，会话关闭后需先重新打开。Remote 不强依赖 settings，无 settings 时仍激活、默认关闭，仅支持会话命令配置；全局写入明确拒绝。全局与会话表单均先按共享 schema 本地校验。

`client.ts` 注册 按 namespace key 注册的 `settings.plugin.item` 卡片和 `conversation.input.left`，后者 order=-10，CSS order=0；专家插件 slot order=0/CSS order=1。无需修改专家或客户端 UI 项目。客户端 bundle 使用宿主 ModuleLoader，React 及 dsh-client-ui-primitives 由宿主提供。Button、Menu、Switch、IconChevronDownOutline14 直接使用公共导出，不打包第二份控件。卡片外壳与插件市场、上下文采用同一策略：按私有 PluginCard 的结构与 token 实现，不读取宿主私有 CSS。聊天摘要只显示开关。全局卡片位于官方“插件配置”TAB，未新增 TAB。会话字段不再提供来源选择器，直接修改产生覆盖，只有覆盖字段显示单项恢复。会话选择项即时保存，数值和文本失焦保存；全局需点击保存。未编辑面板周期刷新，草稿和保存请求不会被旧读取结果覆盖，错误保留供重试。

通过 delegationDepth 判断子代理，读取 parentSession 对应的已加载父会话；默认 subagents=false，父关闭或不可用时子关闭。开启后继承父生效参数，但不继承父失败计数、Loop 实例和命令 ID。普通 fork 不按子代理处理。子代理停用时不注入 PUA 停用说明，减少对专家提示词的干扰。

Loop 参数从会话默认或表单本次值生成启动快照，启动不写回验收默认。修改默认值不改变活动 Loop；关闭总开关立即取消本会话运行。恢复继承可撤销会话覆盖，回退旧包不等于恢复配置数据。

## 状态与生命周期

会话状态从 inheritedEventCount 开始增量读取 snapshotEvents(cursor)，成功命令只解析一次，仍按命令进入顺序折叠。无相关命令变化时复用配置；pending 或 settings 默认值变化时重新折叠已解析命令。pending 覆盖 handler 到 done 间隙，失败撤销。父会话继承日志不参与配置；profile 默认来自 settings，当前会话显式命令优先。有 settings 默认开启/auto，无服务默认关闭。

运行记录为带插件来源的原生 user/message，保存观察计数、最近128个调用ID哈希、Loop配置与结果。每次先 append 完整 RECORD，再同步通过 surface replace 用运行说明替换其模型可见节点，sourceEventSeqs 引用原记录。完整 JSON 只保留在历史日志，恢复仍从 ownEvents 读取；卸载后宿主也能重建替换结果。宿主控制写盘，崩溃前未 flush 的尾部可能丢失。

`session-compat.ts` 根据宿主 `SESSION_FORMAT_VERSION` 构造替换范围：V2 用 `start/end`，V3 用 `startSeq/endSeq`；不试写后重试。日志升级由官方 V2→V3 迁移器负责。0.1.0-rc.8、0.1.1-rc.2 缺少 `SessionLogOffset` 或 `snapshotEvents()`，不在声明范围内。

当前 DSH append 没有暴露 ignorable 参数，自定义必需事件会被持久层拒绝回放，因此不使用新事件类型，也不在 llm/stream 中修改不可变请求。旧会话（包括分叉可见的父记录）在下一次 pre-step 前将尚可见的本插件 RECORD 替换为说明；同名用户文本不受影响。若进程恰在两次 append 间终止，下次加载插件后的 pre-step 会补做替换。历史原始请求不重写。

该实现每次保存增加一条替换事件，会使宿主重建模型上下文缓存；收益是原始 JSON 不再随模型请求累积，简短运行说明仍随历史保留。它不是宿主持久化成本的优化。启动任务的 LOOP_START 仍含完整 verify 命令并对模型可见；ID 校验只保证最新命令接管，不隔离验证文件或环境。

DSH 的 `tools/result` 通知发生在 `tool/result` 事件 append 之前，不能在该通知中写普通消息。现在只更新内存计数和待写标志；按原始日志增量跟踪 assistant 声明的全部调用，等整组结果齐全才 flush。`step/end`、`turn/end` 触发微任务离开禁止重入的事件发布栈，pre-step 和 turn-stopping 也尝试 flush。不是靠固定延时猜测完成；未派发的并行调用同样阻止写入。

卸载在工具组中途发生时，只保留根上下文的待写边界监听；记录写完立即撤销，不注入候选或唤醒模型。真正缺失的结果不补造；安全边界前进程退出可能丢失内存观察。卸载后若结果永不补齐，待写监听保留到根上下文结束。

旧历史在首次 pre-step 修复完整工具组：只跨越精确运行时来源 `@michengai/dsh-pua/runtime` 的节点，所有调用结果齐全后，才用通用 `user/message` 的 `surface replace` 将夹入节点与紧随结果节点投影为原工具结果。工具结果本来就是 user-role，id、tool source、content 完整沿用；原 `tool/result` 及 error/meta 留在原始日志。重复加载幂等，分叉可见历史可修复但不继承父运行状态。无关消息或缺失结果不进行半组修复。证据见[工具消息顺序修复](../07-迭代归档/2026/I003-完整原版移植/03-工具消息顺序修复.md)。

- tools/result 读取终端最终 canonical value，仅暂存；排除取消、拒绝、stdout伪退出码、嵌套字段。成功清零插件的连续终端失败观察；拒绝、取消以及无结构化错误码的宿主错误不累计，也不清零。该观察与原版 SKILL 中由模型判断的任务失败计数不同，“读文件成功不清零”不适用于本插件终端观察。
- 0.1.5 默认持久 pwsh/bash 的 canonical value 是纯文本。`terminal-observation.ts` 仅将尾部非零退出、shell 异常或官方超时首行识别为核验线索；在下一 pre-step、整组结果齐全时合并为一次提示，不计数、不升级 L1–L4。成功的 pwsh 命令可以打印与真实失败完全相同的返回文本，不能将 regex 当成权威退出码。off、取消、clear、卸载后不向后续任务泄漏提示；进程重启不恢复此内存提示。
- 观察2/3/4/5选择原版候选L1/L2/L3/L4，整组完成后的 pre-step 至多注入最新一级；首次失败不打断遵循原版，off 不注入。模板数量不匹配时报明确错误。仍须模型核实当前同一子目标的真实失败，不能机械升级。
- pre-step 只匹配真实用户输入的原版质量纠偏规则；off 不因此复活。
- turn-stopping 只在显式Loop中续轮。Oracle配置来自用户命令；工作区不是不可篡改沙箱。
- Oracle 默认120秒超时（可配置1–3600秒），输出有界；失败继续，上限停止不记完成，取消/卸载/并发off中止验证与续轮。
- 暂停后同会话用户补充才恢复；分叉和普通会话恢复不自动启动Loop。
- compact 后注入最小数字观察；clear 清除运行观察；核心每步按当前状态重新拼装。
- 反馈提醒只看 assistant 可见文本，默认每5次；离线、频率0、子代理和Loop不提醒，不触发模型步骤或记录评分。

## 平台差异

| 原版接口或行为 | DSH实现与限制 |
| --- | --- |
| `/pua:p9` | `/pua p9`，宿主命令名不允许冒号 |
| `~/.pua/config.json` | profile settings，会话显式命令优先 |
| Bash Stop和`.claude/pua-loop*.md` | 原生停止边界与会话日志，不执行setup脚本 |
| 自动推断verify | 使用用户配置的默认或本次验收命令，空则honor system |
| 新会话接管暂停Loop | 同会话补充后恢复，新会话与分叉不自动接管 |
| Claude PID/TTL、tmux、worktree清理 | DSH管理子代理；本插件只取消自有循环，不拥有其他工具资源 |
| integrity-guard的Bash/Python拦截 | 核心治理协议保留，权限由DSH原生策略决定；没有逐条复刻脚本regex拦截 |
| Pro自进化、问卷本地文件 | 完整协议交给模型和宿主文件工具，不增加绕过授权的自动写入器 |
| 全局stop_counter | 会话级计数避免串扰；只提示入口，不自动记录评分 |

“完整原文”不代表所有原版管理脚本在两个宿主中的执行结果完全等价。

## 验证与恢复

真实宿主服务与固定回复适配器验证原文、命令、资料、设置和Loop，真实Git/PowerShell验证索引与退出码。真实模型语气、角色遵循、完成率需另行测试。

卸载撤销贡献、取消自有循环，保留业务文件和宿主日志。旧 tgz 只能在匹配的宿主版本中使用，V3 日志不支持交给 V2 宿主直接读取；配置文档备份不是完整依赖及会话备份。同版本包重打使用新文件名避免缓存。

## 当前运行约束

- 仅统计本会话仍在可见 surface 中的工具调用；turn/end 或新轮次开始后解除历史孤儿阻塞。插件卸载不等于工具结束，不强行插入消息；会话销毁时丢弃无法安全落库的观察并告警、释放引用。
- 每个用户轮次最多四次失败候选。成功清零连续观察，但不重置本轮四次预算；模板异常跳过提示并告警。
- 普通命令限 8 KiB；config/loop-json 为 128 KiB 传输限制，再按 task 4096 字符、verify 8192 字符分别校验。
- esbuild 为最终宿主 bundle 生成对应 sourcemap。兼容测试在系统临时目录建立独立依赖树，清除 NODE_PATH 并核对直接运行依赖的解析路径。
