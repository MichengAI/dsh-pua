# 插件架构

更新时间：2026-09-10 00:30（Asia/Shanghai）

## 原文与接口

基线 PUA 3.5.1 / e6e6cd237ad17750d179674bff52f8184abea8fd，DSH 0.1.2-rc.1。SourceCatalog 先校验字节指纹再加载白名单，不执行原版脚本。核心、展示协议、路由完整进入 systemPrompt，模式追加原文及关联协议。`{{` 字面转义避免宿主插值，其余正文不改写。

组合上限 192 KiB，超限失败不截断。15 风味 × 11 模式及 auto 均校验，当前约 52–101 KiB。pua_reference 仅允许清单内 Markdown，全量返回。

必需 commands、systemPrompt。可选 tools 注册资料和结果观察，settings 注册 michengai-pua，subprocess 提供 Git/Oracle。明确任务 followup，纠偏 steer，非任务控制不唤醒。

## 状态与生命周期

会话状态从 inheritedEventCount 开始增量读取 snapshotEvents(cursor)，成功命令只解析一次，仍按命令进入顺序折叠。无相关命令变化时复用配置；pending 或 settings 默认值变化时重新折叠已解析命令。pending 覆盖 handler 到 done 间隙，失败撤销。父会话继承日志不参与配置；profile 默认来自 settings，当前会话显式命令优先。有 settings 默认开启/auto，无服务默认关闭。

运行记录为带插件来源的原生 user/message，保存观察计数、最近128个调用ID哈希、Loop配置与结果。每次先 append 完整 RECORD，再同步通过 surface replace 用运行说明替换其模型可见节点，sourceEventSeqs 引用原记录。完整 JSON 只保留在历史日志，恢复仍从 ownEvents 读取；卸载后宿主也能重建替换结果。宿主控制写盘，崩溃前未 flush 的尾部可能丢失。

当前 DSH append 没有暴露 ignorable 参数，自定义必需事件会被持久层拒绝回放，因此不使用新事件类型，也不在 llm/stream 中修改不可变请求。旧会话（包括分叉可见的父记录）在下一次 pre-step 前将尚可见的本插件 RECORD 替换为说明；同名用户文本不受影响。若进程恰在两次 append 间终止，下次加载插件后的 pre-step 会补做替换。历史原始请求不重写。

该实现每次保存增加一条替换事件，会使宿主重建模型上下文缓存；收益是原始 JSON 不再随模型请求累积，简短运行说明仍随历史保留。它不是宿主持久化成本的优化。启动任务的 LOOP_START 仍含完整 verify 命令并对模型可见；ID 校验只保证最新命令接管，不隔离验证文件或环境。

DSH 的 `tools/result` 通知发生在 `tool/result` 事件 append 之前，不能在该通知中写普通消息。现在只更新内存计数和待写标志；按原始日志增量跟踪 assistant 声明的全部调用，等整组结果齐全才 flush。`step/end`、`turn/end` 触发微任务离开禁止重入的事件发布栈，pre-step 和 turn-stopping 也尝试 flush。不是靠固定延时猜测完成；未派发的并行调用同样阻止写入。

卸载在工具组中途发生时，只保留根上下文的待写边界监听；记录写完立即撤销，不注入候选或唤醒模型。真正缺失的结果不补造；安全边界前进程退出可能丢失内存观察。卸载后若结果永不补齐，待写监听保留到根上下文结束。

旧历史在首次 pre-step 修复完整工具组：只跨越精确运行时来源 `@michengai/dsh-pua/runtime` 的节点，所有调用结果齐全后，才用通用 `user/message` 的 `surface replace` 将夹入节点与紧随结果节点投影为原工具结果。工具结果本来就是 user-role，id、tool source、content 完整沿用；原 `tool/result` 及 error/meta 留在原始日志。重复加载幂等，分叉可见历史可修复但不继承父运行状态。无关消息或缺失结果不进行半组修复。证据见[工具消息顺序修复](../07-迭代归档/2026/I003-完整原版移植/03-工具消息顺序修复.md)。

- tools/result 读取终端最终 canonical value，仅暂存；排除取消、拒绝、stdout伪退出码、嵌套字段。成功不清零。
- 观察2/3/4/5选择原版候选L1/L2/L3/L4，整组完成后的 pre-step 至多注入最新一级；首次失败不打断遵循原版，off 不注入。模板数量不匹配时报明确错误。仍须模型核实当前同一子目标的真实失败，不能机械升级。
- pre-step 只匹配真实用户输入的原版质量纠偏规则；off 不因此复活。
- turn-stopping 只在显式Loop中续轮。Oracle配置来自用户命令；工作区不是不可篡改沙箱。
- Oracle 120秒超时，输出有界；失败继续，上限停止不记完成，取消/卸载/并发off中止验证与续轮。
- 暂停后同会话用户补充才恢复；分叉和普通会话恢复不自动启动Loop。
- compact 后注入最小数字观察；clear 清除运行观察；核心每步按当前状态重新拼装。
- 反馈提醒只看 assistant 可见文本，默认每5次；离线、频率0、子代理和Loop不提醒，不触发模型步骤或记录评分。

## 平台差异

| 原版接口或行为 | DSH实现与限制 |
| --- | --- |
| `/pua:p9` | `/pua p9`，宿主命令名不允许冒号 |
| `~/.pua/config.json` | profile settings，会话显式命令优先 |
| Bash Stop和`.claude/pua-loop*.md` | 原生停止边界与会话日志，不执行setup脚本 |
| 自动推断verify | 仅接受显式`--verify`，否则honor system |
| 新会话接管暂停Loop | 同会话补充后恢复，新会话与分叉不自动接管 |
| Claude PID/TTL、tmux、worktree清理 | DSH管理子代理；本插件只取消自有循环，不拥有其他工具资源 |
| integrity-guard的Bash/Python拦截 | 核心治理协议保留，权限由DSH原生策略决定；没有逐条复刻脚本regex拦截 |
| Pro自进化、问卷本地文件 | 完整协议交给模型和宿主文件工具，不增加绕过授权的自动写入器 |
| 全局stop_counter | 会话级计数避免串扰；只提示入口，不自动记录评分 |

“完整原文”不代表所有原版管理脚本在两个宿主中的执行结果完全等价。

## 验证与恢复

真实宿主服务与固定回复适配器验证原文、命令、资料、设置和Loop，真实Git/PowerShell验证索引与退出码。真实模型语气、角色遵循、完成率需另行测试。
