# 插件架构

更新时间：2026-09-09 21:50（Asia/Shanghai）

## 宿主接口与依赖

`apply` 依赖 `commands`、`systemPrompt`。插件只注册 `pua` 命令和 `michengai:pua` section，资源由 Cordis 管理卸载。接口基线锁定 DSH 0.1.2-rc.1，不复制宿主实现。

明确任务通过 `agent.followup` 排队；当前任务纠偏和质量检查通过 `agent.steer` 进入最近步骤。开关、状态、帮助与风味设置不唤醒 Agent。成功入队不等于模型已经完成。

## 状态唯一事实源

持久状态来自当前会话 `ownEvents()` 中成功配对的 `command/run`、`command/done`。仅处理 `pua`、有效参数及本插件结果前缀。失败、未完成和分叉继承前缀不生效。按命令进入顺序折叠，以稳定处理并发控制命令。

handler 在审查只读预检完成且未取消后、唤醒之前按 commandId 临时暂存动作，覆盖到宿主写入 done 的短间隙；投递抛错就撤销。临时态按 Session 对象弱引用保存，不能影响另一对象或 profile。重启后仅恢复宿主已保存的成功结果。宿主的写盘时机仍由其 checkpoint/flush 策略控制。

不新增自定义事件，是为了避免旧宿主或卸载后的读取器遇到未知必需事件而拒绝恢复。状态只包含开关及风味；失败次数依据对话，不持久化为机械工具计数。

当前实现每次读取扫描本会话自己的日志。后续若长会话性能测量证明有瓶颈，再引入增量投影；不能为优化改变重放语义。

## 提示词与素材

固定素材清单在 `assets/pua/upstream.json`，Markdown 按原版本机检出字节保存，并记录固定提交 Git 对象指纹；系统提示词仅拼接 DSH 核心契约、当前风味章节、对应方法论。每种提示词限 32 KiB，启动时校验全部风味完整性。双花括号做字面转义，防止触发 DSH 严格变量插值。

风味白名单决定文件名，用户字符串不能作为路径。插件不运行原版 hooks、不读共享 `~/.pua`。原版素材中自动记忆、固定工具、重复验收、扩大任务或调度团队等描述明确受 DSH 适配契约限制。

默认会话无 PUA section 内容；关闭后保留停用说明，抑制历史内容和压缩摘要中的旧风味。分叉默认停用。首版不支持以 `complete` section 替代全部系统提示词的自定义 Agent。

## 交付边界与恢复

本版不自动监听失败、不拦截停止、不自动调用模型 API，不自动清理任何用户文件。卸载撤销命令与提示词贡献，保留宿主会话日志及 Agent 已做的工作。再次安装可以恢复成功配置；需要关闭时先执行 `/pua off`。

输入检查、动态提示词正确注入及功能测试可以离线验证；话术保持、真实任务完成质量和真实桌面体验需要单独评测，不能由离线固定响应适配器证明。

## 0.1.1 审查与质量入口

原版三个快速命令正文独立加载，去除 frontmatter 后放入对应用户请求，不叠加到每个系统提示词。开工、交付旁白和纯分析诊断归核心契约，模型遵循度需实测。

review 始终作为明确只读任务 followup。通过 ctx.get('subprocess') 可选获取宿主服务，使用固定 argv、会话 cwd 和 Git 根路径规格采集索引。总预算 10 秒，stdout 1 MiB、stderr 8 KiB，输出截断和读取失败标为证据缺口；外部取消或插件卸载直接阻止投递。预检不判断提交历史、推送或漏洞。

状态按 command/run 顺序折叠，晚到的 off 不会被较早 review 的迟完成覆盖。旧版成功“任务请求”结果保留旧含义，以免解析器升级改写历史配置。
