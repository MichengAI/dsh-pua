# DSH rc.2 兼容验收

更新时间：2026-09-11 14:10（Asia/Shanghai）

## 支持范围与实现

插件版本为 0.2.1。参考 automation、btw、simplify 等插件使用明确版本列表的方式，开发 DSH 依赖全部精确锁定 0.1.5-rc.2。npm 的 latest 当时仍为 rc.1，next 为 rc.2；本轮以用户指定 rc.2 为目标。

| 宿主版本 | 本轮结果 | 声明支持 |
| --- | --- | --- |
| 0.1.0-rc.8 | 隔离探测缺少 `SessionLogOffset` 导出及现有日志 API，不扩展重写旧宿主日志层 | 否 |
| 0.1.1-rc.2 | 隔离探测缺少 `SessionLogOffset` / `snapshotEvents()` 所需接口 | 否 |
| 0.1.2-rc.1 | 独立依赖树 70/70，0 失败、0 跳过 | 是 |
| 0.1.5-rc.1 | 独立依赖树 73/73，0 失败、0 跳过 | 是 |
| 0.1.5-rc.2 | 开发依赖完整检查 73/73，0 失败、0 跳过；另做真实包隔离安装 | 是 |

0.1.2 不具备新版持久终端及 V2→V3 迁移包，矩阵不装这四个测试依赖、不运行对应三项新版专用测试；其余包括终端文本观察、工具顺序与取消回归全部运行。矩阵脚本固定各目标版本；rc.1 的依赖闭包也显式固定，避免 `^rc.1` 悄然解析为 rc.2。

`session-compat.ts` 按 `SESSION_FORMAT_VERSION` 选择替换范围键，三处调用统一接入。`terminal-observation.ts` 针对持久终端文本提供一次核验提示，不将其当成结构化错误。原版素材、独立 PowerShell Oracle、默认 settings 行为及已有工具结果写入边界均保留。

## 失败与修复证据

1. rc.2 依赖升级后，旧 `surfaceOp` 的 `start/end` 在三处触发 TS2353。改为 V2/V3 边界桥接后类型检查通过。
2. 首轮新版检查 66 项中 12 项失败，原因是旧测试读取 `request.system`，以及历史种子缺少 V3 所需 `assistant/message.stream`。分别改为读取宿主真实 system 消息位置、构造合法历史事件；原文、开关、角色和工具顺序断言继续保留。
3. 新增非零文本、超时和普通文本回归，旧实现对前两种缺少核验提示；实现后通过。取消后提示泄漏回归先失败，非正常 `turn/end` 清除内存提示后通过。
4. 官方迁移测试的前缀长度断言曾漏算 `Session.create()` 追加的 `session/end-seed`。改为以修复前实际快照长度验证，产品逻辑未因此调整。

最终 `npm run check` 包含类型检查、73 项测试和素材/文档校验。版本矩阵通过 `npm run test:compat` 或带目标版本参数执行；依赖隔离目录结束后自动清理。`verify` 还检查 peer 范围一致、开发依赖同版锁定及锁文件一致性。

## 验证边界与恢复

- 持久终端用例运行官方 pwsh/bash 工具包装与 ToolRuntime，PTY 后端是确定性内存夹具。pwsh 的真实非零退出与成功命令打印同名标记可产生完全相同的返回文本，故只能提示核验；不把内存夹具称为真实桌面 PTY 验收。
- 历史迁移用例执行官方 V2→V3 逻辑事件迁移阶段，再加载 Session、修复 PUA 插入并重载；原事件、工具结果身份和正文保留。没有读取或迁移磁盘上的用户会话。
- 固定回复适配器验证实际请求与生命周期，不证明真实模型语气、任务成功率或钉钉 HTTP 请求已经通过。settings schema 测试也不等于桌面交互验收。
- 用户此前要求卸载插件，本轮保持 web profile 未安装。重新测试需使用 0.2.1；旧 0.2.0 包仅适用于其旧宿主，不支持 rc.2。V3 日志不能交给旧宿主直接读取，回退需匹配版本的独立环境及迁移前数据。
- 本轮未提交、推送或发布；许可复核、产品验收与 findstr 原管道环境差异继续由[待办](../../../00-交接入口/03-待办与阻塞.md)承接。

上轮工具顺序的具体边界见 [I003 修复记录](../I003-完整原版移植/03-工具消息顺序修复.md)；现行技术规则见[插件架构](../../../03-技术架构/01-插件架构.md)。
