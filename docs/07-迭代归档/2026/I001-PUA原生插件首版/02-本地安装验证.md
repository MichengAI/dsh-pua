# 本地安装验证

更新时间：2026-09-09 21:15（Asia/Shanghai）

用户在首版交付后明确要求安装到本地测试，本次在现有 `web` profile 安装 0.1.0，不修改其他插件的直接依赖声明。

## 环境与操作

- DSH：0.1.2-rc.1；profile：`web`。
- 安装来源：本项目 `michengai-dsh-pua-0.1.0.tgz`。
- 执行：`dsh plugin --profile web add <本地包绝对路径> --ignore-scripts --registry=https://registry.npmjs.org/`，成功退出。
- 安装前将 profile 的 package.json、pnpm-lock.yaml、cordis.yml、cordis.patch.yml、pnpm-workspace.yaml 备份到用户目录 `.dsh/backups/dsh-pua-install-20260909-211411`。这是配置与依赖清单备份，不是完整 node_modules 回滚副本；不随项目分发。

## 验证结果

- profile 依赖加入 `@michengai/dsh-pua`，bundle 列表包含该包。
- `dsh --profile web --dump-config` 正常解析，存在 `michengai-pua` 条目；仅提取匹配插件的行，没有输出完整配置。
- 从实际安装位置解析宿主依赖，在临时内存会话验证真实命令注册、华为风味渲染、关闭模式和卸载，通过后销毁检查上下文。
- 其他已有插件的直接依赖声明未变。安装器提示 profile 存在 peer dependency 警告，本插件的实际依赖解析与加载通过；未宣称对整个 profile 进行完整审计。
- 没有发送模型请求，没有读写用户会话，没有强制关闭桌面进程。桌面正在运行时由宿主处理配置重载；若未显示命令，结束当前工作后重载后端或重启桌面端。

## 测试入口与恢复

先输入 `/pua help`，再输入 `/pua flavor huawei`，最后 `/pua 你的测试任务`。用 `/pua status` 查看状态、`/pua off` 关闭当前会话模式。

如需卸载，执行 `dsh plugin --profile web remove @michengai/dsh-pua` 并按宿主要求重载。安装包属于本地文件依赖，请保留项目根目录中的 tgz，便于未来重新安装。

实际桌面交互与模型行为由用户继续测试；[初次开发验收](01-验收记录.md)中的“未安装”描述属于该次验收时点，以本记录为后续安装事实。
