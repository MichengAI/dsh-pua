# 工具消息顺序修复

更新时间：2026-09-10 00:42（Asia/Shanghai）

## 问题与根因

用户报告钉钉天气查询在终端失败后出现 HTTP 400。天气脚本路径错误是触发失败的独立问题；PUA 在工具结果前插入消息会影响所有同类终端失败，修复范围不包含天气技能路径。

DSH 0.1.2-rc.1 在工具 finalize 中通知 `tools/result`，随后 AgentLoop 才 append `tool/result`。旧运行时在通知中同步保存 RECORD 和替换说明，形成“assistant 调用 → PUA 消息 → 工具结果”。从实际已安装依赖运行离线适配器复现了两次并行调用之间的插入；结果存在，Session 重载仍保留错误顺序。HTTP 400 来自用户实测，本轮没有调用外部模型复现 HTTP 响应。

## 修复与边界

- 结果通知只暂存观察；追踪整组已声明调用，全部结果落库后才写运行记录。明确的 step/end、turn/end 以及下一步骤作为写入边界，事件回调通过微任务避开禁止重入的 append。
- 下一 pre-step 向本步 messages 添加一条最新候选，保留首次失败不注入和当前开关门控；不在结果通知中 inject。
- off、取消、卸载共用同一写入保护。卸载时仅延续待写记录的边界监听，完成即撤销，不唤醒模型。
- 旧会话在首次 pre-step 检查工具组。仅当全部结果齐全且间隔消息均来自本插件运行时，追加原生 surface replace，将间隔 PUA 节点与后续结果投影为原工具结果。完整保留结果 id、source、content；原始事件和 error/meta 不变，不重跑工具。卸载后可独立重载，重复处理幂等。
- 同名用户消息、其他来源消息和真正缺失结果不自动修复；分叉历史可修复，但不继承父会话运行状态。进程在安全写入前退出可能丢失尚未持久化的观察；永久缺失结果会阻止待写记录落库。
